## Unreleased

The all-channel service. Every entry below is a change from v0.1.0.

- CI publishes the image only for a release tag; a push to `main` no longer publishes `:main`. The secret scan reads `.gitleaks.toml`, which allows the placeholder credentials in tests. Dependabot also watches `ui/`.
- API and UI: registration asks for your Plivo account's Auth ID and Auth Token, and a sub-account's Auth ID and Auth Token work the same way. `tenant_exists` reads "this Plivo account is already a tenant" and `<what>_not_in_account` reads "the Plivo account does not hold this <what>"; the codes are unchanged.
- UI: an action Plivo refuses shows Plivo's own reason and status, for example "Insufficient balance (402)".
- Upgrade: sessions minted before this release cannot renew, because they carry no renewal chain. Each user needs an email and a password, set by an administrator under Settings, Users or with `PATCH /agents/{id}` and `POST /agents/{id}/password`, before they sign in again.
- UI: the call card sits above the conversation instead of over it; a call offer names the number the call came in on; Conversations shows an unheld queued conversation as Waiting; the status menu reloads statuses when it opens; the operator fields accept the `HS_OPERATOR_KEY=` line and empty after the request, and the sign-in toast no longer tells you to choose a status the header already shows. `docker/up.sh` prints the operator key command that yields the bare key, and Logs and Stop commands that name the compose project in use.
- UI: a resolved or cancelled task opens read-only; an internal contact made with a URL lists and edits its URL; Conversations names a task by its title; a disabled queue is marked in every number picker, and a queue's sheet names what routes to it before it is disabled; the delete error names what uses the row; offers sit above the desk and no longer cover the open conversation; the operator key is used for one request and kept nowhere; a desk that cannot renew, and a failed sign-in, say to ask an administrator for a password.
- Fix: saving a built-in agent status (rename, recolor) answered 422 "Extra inputs are not permitted"; it now saves. A built-in status keeps its availability, and a change to it answers 409 `status_default`.
- UI: a user's password buttons stay off until the user has an email; an email another user has names that user; Who are you? adds a person with an email and password; a registration that finds its Plivo account already registered offers a new organization key; setting your own password says it signs you out, then returns to sign-in with the reason.
- Channels: besides voice, the service queues, routes and runs SMS, WhatsApp, email, chat, callback and agent-task conversations, with transfers, wrap-up, dispositions, supervisor controls, reports, views, export and search.
- Postgres schema `hs`: one baseline migration creates every table in `hs`, with Alembic's version table, and nothing in `public`. `HS_VERSION_SCHEMA` keeps the version table in another schema; see [docs/configuration.md](docs/configuration.md#sharing-a-database).
- Breaking: this release drops the upgrade from v0.1.0. Install it on a new database. On a database v0.1.0 used, `alembic upgrade head` builds an empty schema `hs` and copies nothing from v0.1.0's tables in `public`.
- Breaking: `HS_OPERATOR_KEY` must be at least 32 bytes, as `HS_SECRET_KEY` already had to be; the service refuses to start with a shorter one. Generate it with `openssl rand -base64 32`.
- The image installs `tzdata-legacy`, so business hours accept every time zone name a browser offers (`Asia/Calcutta`, `Europe/Kiev`, `America/Buenos_Aires`, and the rest of the legacy names). A skill with a minimum above its maximum is told that `max_level is below min_level`.
- Deleting an agent or a tenant no longer waits on Plivo: the request answers once the change commits, and the job pool deletes the Plivo endpoint or application at once and retries on its backoff until Plivo answers.
- A text or task whose every agent who could take it was offered it, in a queue with no text wait timeout for its channel, leaves the queue as `assignment_failed` instead of staying active with no agent: a text closes with the Agent assignment failed disposition, and a task reads failed. The customer's next text opens a new conversation. An email still waits for an agent.
- An assignment failure no longer withdraws an offer made just before it ran: a strict sticky contact whose agent comes free right after its first round found the agent unable, or a call offered to another agent right after Plivo refused a ring, keeps that offer, and fails as `assignment_failed` once that offer ends untaken.
- A text or task that waits for the one agent not yet offered it leaves the queue as `assignment_failed` once an administrator deletes that agent or takes away the team or skill its route needs. It used to stay queued with no offer, no round and no timer.
- Fix: deleting a queue that conversations wait in answers 409 `queue_in_use` with `details.waiting`, how many wait. Disable the queue so it takes no new ones, and delete it once they are taken or closed. The delete used to answer 204, and its waiting conversations were never offered again on any channel. A call waited out its wait timeout or the call-session timeout, and a text with no wait timeout stayed queued. The UI's delete error says how many wait and what to do.
- Fix: deleting a queue that an open task or callback is scheduled for answers 409 `queue_in_use` with `details.scheduled`, how many; give them another target or cancel them first. A task or callback routed again after its queue was deleted, by a new schedule or `reroute`, closes as `enqueue_failed` when it comes due. It used to stay `todo` and `scheduled` while its route failed on every retry.
- A waiting call whose every agent was offered it rings them again once 300 s pass with no new offer, until its rounds are spent or its wait timeout ends it. It used to wait for one of them to change status or load, and with no wait timeout could hold the caller until the call-session timeout.
- `docker/up.sh` checks from inside the `hs` container that `PLIVO_API_URL` answers, and stops with what to do when it does not; its closing hint names the UI's **Register an organization** tab.
- `docker/up.sh`: `--no-ui` starts the stack without the UI; a URL argument is checked before it is saved; the re-apply hint appears only when the URL differs from the last healthy start's; compose names its images after the project, so two checkouts no longer re-tag each other's.
- Job lanes: every job row carries its lane, so a backlog in one lane never slows another lane's claim. Webhook deliveries run on a lane of their own, and a subscription whose endpoint timed out or refused the connection rests for 30 seconds.
- Redis for hot state: heartbeats, agent slots, open offers, offer rounds, sticky agents, unread counts and a config cache. Redis 7 or later is required, the service refuses to start on an older one, and Redis must run with `maxmemory-policy noeviction`; the sweep rebuilds what a Redis loss takes from Postgres or restarts it, per [docs/configuration.md](docs/configuration.md#run-redis). Postgres 14 or later is required.
- Breaking: a queue's `text.messages` is keyed by channel, and a single set of lines answers 422.
- Logs: the UI container's Caddy log replaces the value of an `access_token` query parameter, so a desk's stream token no longer lands in its warnings; HS's own access log already did.
- Fix: a row read back and sent unchanged is accepted. `PATCH /dispositions/{id}` on a system disposition and `PATCH /tasks/{id}` on a task being routed answer 200 when no field differs, and `waiting: false` on a conversation that is not marked is a no-op on any channel. The agent who dials with `POST /calls` can read the new conversation while its leg rings; its teammates and supervisors read it once the leg answers. A `waiting` sent back as it reads is a no-op for anyone who can read the conversation; changing it still takes the agent on it.
- Fix: a Plivo refusal's `errors` no longer carry the tenant's auth ID or a URL's user and password, and the service log redacts a URL's user and password. Both also redact the value of any name that contains `token` or `credential`, or that is `key`, so a signed audio URL that Plivo echoes keeps none of its `token`, `key`, `X-Amz-Credential` or `X-Amz-Security-Token` values.
- Breaking: the `offer.created` event carries `to`, the business number the contact reached.
- Breaking: `/reports/calls` and `/reports/dispositions` are removed. `/reports/conversations` and `/reports/conversations/rows` give the numbers per conversation.
- Breaking: a queue's `strategy` is `availability`, `simultaneous`, `fewest_handled` or `least_handle_time`, and its `dequeue_order` is `fifo` or `lifo`. A status `color` is any `#RRGGBB`. Conversations no longer read `label`, and the `conversation_labels` setting is gone: derive a label from `state` and `awaiting`. A JSON enqueue answers only `conversation_id`.
- Changed: a queue's `capacity` runs from 1 to 10,000, its `wait_timeout_sec` up to 86,400, a route's `retries` up to 10, and skill levels from 0 to 100. Every default stays.
- Changed: search's team filter and team words use the teams the handling agents were in when the conversation closed, a snapshot, not the queue's teams.
- Plugins: [docs/plugins.md](docs/plugins.md) lists the names a plugin may rely on across versions and the recipe for a derived image; `examples/plugin` is a working plugin, built in CI.
- Search over closed conversations reads OpenSearch when `SEARCH_URL` is set, and Postgres otherwise.
- `docker/up.sh https://<public URL>` starts the compose stack with the UI: it checks Docker, writes `docker/.env` with fresh keys where they are empty, and prints where to open the UI, or why a step failed.
- Sign-in: an agent signs in with its email and a password (`POST /sessions`), and its desk renews the session with `POST /me/sessions` for 12 hours, so no one sends it a new link. On an install with more than one tenant, the sign-in names its tenant. Failed tries are limited per email in a tenant and per client address, an IPv6 client by its /64. An admin's session runs the tenant's settings without the tenant key, and a settings write that waited for its admin's demotion answers 401. See [docs/api.md](docs/api.md#auth).
- An optional reference UI in `ui/`, a React app: tenant registration, setup, an agent desk with the Plivo softphone, a supervisor floor and recent conversations. `docker compose --profile ui up` serves it and the API on one port.
- The reference UI is one app: after the organization key signs in, it asks who you are, then shows your status and a dialer on every page and renews your session. Right after registration, **Get started** adds you, a General queue, your number's route and three wrap-up outcomes, so calls work at once. The UI says organization where the API says tenant.
- Reference UI setup: a number's sheet sets its business hours and after-hours action, and every save keeps what you did not change; business hours close on the holidays checked from their list; a refused request names each field and why; an error toast no longer covers or closes a sheet; a key that stops working returns to sign-in; deletes and duplicate names ask in the page; lists search what they show and refresh; copy uses plain words.
- Reference UI sign-in: people sign in with their email and password, from their organization's sign-in link when the server has more than one; every desk renews itself for 12 hours without a new link; an admin runs Settings as themselves with no key; a user's sheet edits, removes and signs out a user and sets their password, and queues and numbers can be deleted. The UI's cap is 5,000 lines of app code.
- Reference UI desk: SMS, WhatsApp, chat, email, task and callback offers ring in the same card as calls; the agent accepts or declines, reads a text's thread live and replies, resolves a task or calls a callback's customer, ends the conversation and wraps up, and holds calls, texts and tasks at once, each a line in My Conversations. The Conversations screen shows a text's messages, and a time from another day shows its date.

## v0.1.0 (2026-11-02)

The first public release: the voice engine. It answers calls on Plivo, runs menus and business hours, queues callers, offers calls to agents and controls the live call, with an HTTP API, a live event stream and signed webhooks. Apache-2.0.
See [docs/limitations.md](docs/limitations.md) for what it does not do.
